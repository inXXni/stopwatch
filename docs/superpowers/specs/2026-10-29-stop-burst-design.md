# 停表爆裂设计文档

日期：2026-10-29
基础：`2026-10-29-stop-hit-design.md`（下称「冲击设计」）

## 1. 背景与目标

停表冲击上线后，用户觉得拍击的力量感还不够。用户在演示里对比了三种加强预设：
重锤（顿帧、往下砸、压扁回弹、闪光）、爆裂（顿帧、镜头推近、放射线、双环、色散）、全开，
还对比了是否加低音，最后选定：

- **爆裂**：在冲击设计的整屏抖动、数字弹、冲击环之上，加顿帧、镜头推近、放射线、第二道冲击环、色散
- **滴 + 低音咚**：停表那一拍在原来的「滴」之外，同时响一声低音「咚」

开始那一拍保持不动；手机振动不做。

## 2. 什么时候播

与冲击设计相同：普通模式（含 `?green`）与 PK 模式下停表那一刻，冲击停表那一格。
开始、清零（清场）、锁定期内被吞掉的拍、计时中都不播。

- 系统开了「减弱动态效果」（`prefers-reduced-motion: reduce`）时，画面上的效果全部不播；
  低音「咚」不是动态效果，照常响。
- 提示音的「滴」不变：除清屏那一拍外每拍都响。「咚」只在停表那一拍响，
  提示音设计里「开始与停表用不同的声音」这条非目标由本设计取代。

## 3. 动画

参数与演示一致，演示里的像素按手机横屏 800×360 换算成 vmin（1 vmin = 3.6 px）。

### 时间线

停表那一刻记为 0。前 70 ms 是**顿帧**：画面定格在被打中的那一下——数字放大到 1.15 倍、
镜头推近到 1.08 倍、色散的残影拉到最开，都停住不动；抖动、冲击环、放射线还没出现。
70 ms 起一齐放开：

| 部分 | 作用在 | 开始 | 时长 | 结束 | 顿帧期间 |
|---|---|---|---|---|---|
| 数字回落 | 停表那一格 `.display` 的 `transform` | 70 ms | 320 ms | 390 ms | 停在第一帧 |
| 色散收拢 | 同一个 `.display` 的 `filter` | 70 ms | 200 ms | 270 ms | 停在第一帧 |
| 镜头拉回 | `<body>` | 70 ms | 300 ms | 370 ms | 停在第一帧 |
| 整屏抖动 | `#stage` | 70 ms | 380 ms | 450 ms | 不出现 |
| 放射线 | 那一格的 `.hit-lines` | 70 ms | 280 ms | 350 ms | 不出现 |
| 冲击环 | 那一格第一个 `.hit-ring` | 70 ms | 500 ms | 570 ms | 不出现 |
| 第二道环 | 那一格第二个 `.hit-ring` | 160 ms | 420 ms | 580 ms | 不出现 |

「停在第一帧」用 `delay` 加 `fill: 'backwards'` 实现；「不出现」只用 `delay`。

### 各部分关键帧

**数字回落**：整段 `ease-out`，关键帧之间线性。替换冲击设计里的「数字弹一下」。

| 进度 | 0 | 0.45 | 0.7 | 1 |
|---|---|---|---|---|
| 缩放 | 1.15 | 0.97 | 1.02 | 1 |

**色散**：数字两侧各拖出一份偏色的影子，向数字收拢并淡出，`ease-out`。
用三层 `drop-shadow`，最后一层是数字原有的光晕，前后不变：

| 进度 | 青色影子 | 品红影子 |
|---|---|---|
| 0 | 偏移 (−1.9, 0.3) vmin，`rgba(0, 229, 255, 0.95)` | 偏移 (1.9, −0.3) vmin，`rgba(255, 43, 214, 0.95)` |
| 1 | 偏移 0，透明 | 偏移 0，透明 |

**镜头**：整页以停表那一格数字的中心为原点缩放，1.08 → 1，`ease-out`。

**整屏抖动**：与冲击设计相同（位移最大 3.04 vmin，380 ms），只是推迟到顿帧之后。

**放射线**：14 根线围成一圈，以数字中心为圆心，长短交替，`ease-out`：

- 第 k 根（k = 0…13）的方向角为 k × 360° / 14 + 6.3°
- 偶数根是长线，从半径 22.2 vmin 画到 59.7 vmin；奇数根是短线，从 26.4 vmin 画到 47.2 vmin
- 线宽 0.8 vmin，圆头，颜色与冲击环相同
- 整组从 0.6 倍放大到 1.35 倍，不透明度 1 → 0

**冲击环**：与冲击设计相同（外径 8.3 → 138 vmin，500 ms），推迟到顿帧之后。

**第二道环**：比第一道晚 90 ms、更细更小，`ease-out`，颜色与第一道相同：

| 进度 | 外径 | 线宽 | 不透明度 |
|---|---|---|---|
| 0 | 7.2 vmin | 1.7 vmin | 0.8 |
| 1 | 106 vmin | 0.3 vmin | 0 |

## 4. 低音「咚」

> 2026-10-29 起「咚」的音量放大到 3 倍（三角波 2.1、敲击 1.5），「滴」和「咚」经同一个软限幅出口，
> 见 `2026-10-29-thump-loud-design.md`。下文的音量数值是改动前的。

与「滴」同一时刻开始，各响各的，互不打断。用 Web Audio 实时合成：

- **音高**：三角波，0.14 秒内从 300 Hz 指数滑到 70 Hz。手机喇叭放不出真正的低音，
  从中频往下滑，小喇叭也听得出分量
- **音量**：4 ms 内从静音升到 0.7，之后指数衰减，0.3 秒时到 0.001，0.32 秒停
- **敲击声**：30 ms 白噪声，幅度按 (1 − 进度)³ 衰减，经 2500 Hz 低通，增益 0.5

## 5. 不影响计时

- 成绩在拍击那一刻按事件时间戳算好、写到屏幕上了，动画与声音都在那之后。
- 画面效果最晚 0.58 秒结束，比 500 ms 的锁定期多出 80 ms。锁定期一过，下一拍照常生效；
  这时还在播的只有两道环的尾巴。下一拍在普通模式下是清零，在 PK 模式下是另一方开始，
  都不播冲击。另一方最快在这 80 ms 里停表时，两格各播各的，互不干扰。
- 动画只改 `transform`、`opacity`、`filter` 与环的尺寸，不改排版。
- 浏览器不支持 Web Animations API 时画面静默跳过；不支持 Web Audio 时「咚」静默跳过。

## 6. 实现

### DOM

每格在 SVG 后面放两个冲击环和一组放射线：

```html
<span class="hit-ring"></span>
<span class="hit-ring"></span>
<svg class="hit-lines" viewBox="-60 -60 120 120" aria-hidden="true"></svg>
```

放射线的 14 根 `<line>` 由 `app.js` 启动时按 `hit.js` 导出的坐标画进去，坐标单位就是 vmin
（SVG 宽高 120 vmin，`viewBox` 也是 120）。

### CSS

- 环与放射线的颜色改由格子上的 `--hit` 变量决定：默认 `--ink-hit`，PK 蓝方 `--ink-blue-hit`，
  带 `?green` 时 `--ink-green-hit`。`.hit-ring` 的边框色与 `.hit-lines` 的描边色都取 `var(--hit)`。
- `.hit-lines`：绝对定位，宽高 120 vmin，`transform: translate(-50%, -50%)`，平时不透明度 0，
  `z-index: 1`，`overflow: visible`，`pointer-events: none`；线宽 0.8、圆头。

### `hit.js`

```js
export const HITSTOP_MS = 70;
export const BURST_LINES; // 14 根放射线的 { x1, y1, x2, y2 }，单位 vmin
export function stopHit({ digits, rings, lines, stage, camera }) // 播一次停表爆裂
```

- 先算出数字中心：写到两个环与放射线的 `left`、`top`（相对 `stage`），
  以及镜头的 `transform-origin`（相对 `camera`）。
- 关键帧写成模块里的常量；`digits.animate` 调两次，一次 `transform`、一次 `filter`。

### `beep.js`

`createBeeper()` 返回的对象加 `thump()`，与 `beep()` 共用同一个音频环境。

### `app.js`

- `hitParts` 每格带上 `rings`（两个 `.hit-ring`）、`lines`、`camera: document.body`。
- 停表分支在 `stopTiming` 之后：`hit(i)`（受「减弱动态效果」控制）与 `beeper.thump()`（不受）。

### 离线

不新增文件，`sw.js` 的 `CACHE` 版本号加一。

### 文档

- 冲击设计、提示音设计里被取代的条目改为指向本文档。
- 主设计交互一节的停表冲击那一条改写为爆裂。

## 7. 非目标

- 开始那一拍的画面效果
- 手机振动
- 重锤预设里的往下砸、压扁回弹、闪光
- 效果或力度做成可调

## 8. 测试策略

单元测试：

- `hit.js`：各部分时长、延迟与是否停在第一帧符合第 3 节；数字回落、色散、镜头、放射线、
  两道环的首尾关键帧；环、放射线与镜头原点落在数字中心，`#stage` 整体平移时不变；
  放射线 14 根、长短交替、都在 `viewBox` 内；全部动画 0.6 秒内结束；不支持 `element.animate` 时什么都不做。
- `beep.js`：`thump()` 用三角波从 300 Hz 起振、0.32 秒停，带一段噪声；与 `beep()` 共用音频环境；
  `thump()` 不会打断正在响的「滴」；没有 Web Audio 或出错时静默跳过。

在 headless Chrome 里检查：

| 场景 | 预期 |
|---|---|
| 普通模式、PK 红方、PK 蓝方停表 | 停表那一格出现第 3 节表里的七段动画，时长与延迟一致 |
| 停表 | 响一声「咚」（多出一个三角波振荡器）；开始、清零、锁定期内拍不响 |
| 开始、清零（清场）、锁定期内拍 | 不新增动画 |
| 各种屏幕 | 两道环、放射线的中心与数字中心重合 |
| 模拟「减弱动态效果」 | 停表没有动画，「咚」照响 |
| 动画播完之后 | `<body>` 没有残留的 `transform`，数字的 `filter` 回到原来的光晕；复跑脊柱外观检查 |
| 停表 | 成绩仍按按键事件的时间戳计算 |

另截取顿帧期间与之后的几帧，确认数字放大、色散、镜头推近、放射线与两道环都出现。

## 9. 验收标准

1. 停表那一刻画面先顿 70 ms（数字放大、镜头推近、色散拉开），随后整屏抖动、放射线与两道环扩散，0.6 秒内结束
2. 停表那一拍同时响「滴」和「咚」，其余拍只响「滴」，清屏那一拍不响
3. 开始、清零（清场）、计时中没有画面效果
4. 动画播完后，各种屏幕下的外观与位置和现在完全一致
5. 开了「减弱动态效果」时没有画面效果，声音照旧
6. 计时结果的取得方式不变
7. 断网打开照常播放
8. 全部 `node --test` 测试通过
