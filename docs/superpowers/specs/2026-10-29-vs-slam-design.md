# VS 新一轮砸入设计文档

日期：2026-10-29
基础：`2026-10-28-pk-vs-spine-design.md`（下称「脊柱设计」）

## 1. 背景与目标

VS 放大并与色条连成竖脊之后，用户的反馈是 VS 还是没有比赛的感觉。格斗游戏里的 VS
总带着一股冲击力。用户在演示里对比了四种字效（现状、立体金字、红蓝分色加闪电、爆炸徽章）
与三种动效（无、新一轮砸入、持续电光）后选定：

- **字效保持现状**：琥珀色粗斜体加光晕，不变
- **加「新一轮砸入」动效**：每开始新的一轮，VS 从屏幕外砸下来，撞击时放出一圈冲击环，整屏抖一下

## 2. 什么时候砸

只在 PK 模式下（普通模式没有 VS）：

| 时机 | 砸不砸 |
|---|---|
| 打开页面，字体加载完、排版就绪之后 | 砸一次 |
| 清场（两人都停后再拍一下，`RESULT` → `WAIT_P1`） | 砸一次 |
| 开始、停表、锁定期、计时中 | 不砸 |

- 脊柱设计里的三种排法（宽屏横屏的色条脊柱、竖屏的居中放大、其余横屏的原样）都砸，
  砸的是各自位置上的 VS。
- 系统开了「减弱动态效果」（`prefers-reduced-motion: reduce`）时不砸，VS 直接静止显示。

## 3. 动画

三部分同时开始，共 0.56 秒。参数与演示一致，演示里的像素按手机横屏 800×360 换算成 vmin
（1 vmin = 3.6 px）。

### VS 文字

| 进度 | 缩放 | 旋转 | 不透明度 | 到下一帧的缓动 |
|---|---|---|---|---|
| 0 | 3.4 | −12° | 0 | `cubic-bezier(.55, 0, 1, .45)`（加速下落） |
| 0.42（撞击） | 0.8 | 3° | 1 | `ease-out` |
| 0.66 | 1.12 | −1° | 1 | `ease-in-out` |
| 1 | 1 | 0° | 1 | — |

以文字中心为原点缩放、旋转。只有文字砸下来；脊柱排法里截断色条的那块黑底不跟着缩放，
始终在原位。

### 冲击环

撞击时刻（进度 0.42）从 VS 中心出现，白色圆环向外扩散：

| 进度 | 直径 | 线宽 | 不透明度 |
|---|---|---|---|
| 0 ～ 0.42 | 2.2 vmin | 3.3 vmin | 0 → 1 |
| 1 | 106 vmin | 0.3 vmin | 0 |

缓动 `ease-out`。环会超出屏幕，被页面裁掉。

### 整屏抖动

撞击后整个画面（`#stage`）平移抖动，排版不变：

| 进度 | 0 ～ 0.42 | 0.5 | 0.6 | 0.72 | 0.85 | 1 |
|---|---|---|---|---|---|---|
| 位移（vmin） | 0, 0 | −1.9, 1.1 | 1.7, −1.1 | −1.1, 0.6 | 0.6, −0.3 | 0, 0 |

## 4. 不影响计时

- 动画只改 `transform`、`opacity` 与冲击环的尺寸，不改两格的排版，色条高度、数字大小不受影响。
- 页面刚打开与清场时都不在计时。砸入期间拍下开始，照常计时，动画继续播完，互不干扰。
- 浏览器不支持 Web Animations API（`element.animate`）时静默跳过，VS 静止显示。

## 5. 实现

### DOM

VS 由一层改为三个元素：

```html
<div class="vs" aria-hidden="true">
  <span class="vs-box"><span class="vs-text">VS</span><span class="vs-ring"></span></span>
</div>
```

- `.vs-box`：原来的 `<span>`。脊柱排法里的黑底、宽度、`z-index` 都在它身上。
  各排法下都设 `position: relative`，作为冲击环的定位容器。
- `.vs-text`：文字本身，`display: inline-block`（行内元素不能做 `transform`），光晕挂在它身上，
  动画只作用于它。
- `.vs-ring`：冲击环，绝对定位在 `.vs-box` 中心，平时不透明度为 0。

原来以 `.vs span` 为选择器的规则改为 `.vs-box`、`.vs-text`，静止时的外观与现在完全一致。

### 新模块 `slam.js`

```js
export const SLAM_MS = 560;
export function slamIn({ text, ring, stage }) // 从头播放一次砸入；不支持 element.animate 时什么都不做
```

三段关键帧写成模块里的常量。每次调用都从头播放；上一次还没播完时再调用，新的直接覆盖旧的。

### `app.js`

- `document.fonts.ready` 之后，在两格重新量完尺寸、色条与 VS 就位之后调用一次
- `handleSlapPk` 的清场分支调用一次
- 调用前用 `matchMedia('(prefers-reduced-motion: reduce)')` 判断，开了就不调用

### 离线

`slam.js` 加入 `sw.js` 的 `ASSETS`，`CACHE` 版本号加一。漏加的话，
现有的「页面用到的每个 JS 模块都在缓存清单里」测试会失败。

## 6. 非目标

- 换字效（立体金字、红蓝分色、爆炸徽章）
- 持续的电光、闪烁、旋转
- 砸入音效
- 开始、停表时的动效

## 7. 测试策略

单元测试：现有的离线完整性测试覆盖 `slam.js` 是否进了缓存清单。

在 headless Chrome 里检查（`.vs-text` 上的动画用 `getAnimations()` 读出来）：

| 场景 | 预期 |
|---|---|
| 打开 `?pk`，字体加载完 | `.vs-text`、`.vs-ring`、`#stage` 上各有一段 560 ms 的动画 |
| 红方开始、停表，蓝方开始、停表 | 不新增动画 |
| 清场 | 再砸一次 |
| 模拟「减弱动态效果」 | 打开与清场都不砸 |
| 打开 `/`（普通模式） | 没有动画 |
| 动画播完之后 | 复跑脊柱设计的外观检查，排版与改动前一致 |
| 砸入期间拍下开始 | 成绩仍按按键事件的时间戳计算 |

另截取砸入过程中的几帧，确认 VS 从大到小砸下、冲击环与抖动出现，黑底不跟着缩放。
手机真机上看一眼效果与流畅度。

## 8. 验收标准

1. PK 模式打开页面时，VS 从屏幕外砸下来，撞击时出现冲击环、整屏抖一下，0.56 秒内结束
2. 每次清场再砸一次；开始、停表、计时中不砸
3. 静止时 VS 的外观与位置和现在完全一致，三种排法都是
4. 开了「减弱动态效果」时不砸
5. 普通模式不受影响
6. 计时结果的取得方式不变
7. 断网打开照常砸入
8. 全部 `node --test` 测试通过
