# 停表冲击设计文档

日期：2026-10-29
基础：`2026-10-29-vs-slam-design.md`（下称「砸入设计」）

> 后续：停表效果已加强为「爆裂」，见 `2026-10-29-stop-burst-design.md`。本文的整屏抖动与第一道冲击环原样保留，
> 「数字弹一下」被顿帧后的回落取代，停表那一拍另加了低音「咚」。

## 1. 背景与目标

VS 砸入做好之后，用户想让停表那一下也有同样的震感。用户在 PK 演示里对比了三种停表效果
（无、整屏抖动、抖动加冲击）与三档力度（轻、中、强），选定「抖动加冲击，强」，
随后要求普通模式也一样：

- 停表那一刻，整屏抖一下；停表那一格的数字弹大一下再落回，
  并从数字中心扩散出一圈本格颜色的浅色环

红蓝设计（`2026-10-28-pk-red-blue-design.md`）曾把「停表闪烁或其他任何停表动效」列为非目标，
当时否掉的是「停表时数字闪两下」：数字一闪一灭，看不清成绩。这次的冲击不让数字消失，
读数从停表那一刻起就不再变，所以这条非目标由本设计取代。

## 2. 什么时候播

| 模式 | 时机 | 冲击哪一格 |
|---|---|---|
| 普通（含 `?green`） | 停表（`RUNNING` → `LOCKED`） | 唯一那一格 |
| PK | 红方停表（`RUN_P1` → `LOCK_P1`） | 红方 |
| PK | 蓝方停表（`RUN_P2` → `LOCK_P2`） | 蓝方 |

- 开始、清零（清场）、锁定期内被吞掉的拍、计时中都不播。
- 普通模式横竖屏都播；PK 模式在脊柱设计的三种排法下都播，冲击的是各自位置上的数字。
- 系统开了「减弱动态效果」（`prefers-reduced-motion: reduce`）时不播，与砸入一致。

## 3. 动画

三部分在停表那一刻同时开始。参数与演示里「强」（力度系数 1.6）一致，演示里的像素按
手机横屏 800×360 换算成 vmin（1 vmin = 3.6 px）。两种模式参数相同。

### 整屏抖动

整个画面（`#stage`）平移抖动，共 0.38 秒，线性插值。形状与砸入撞击后的抖动相同，
幅度是它的 1.6 倍，且停表时立刻开抖，不等：

| 进度 | 0 | 0.14 | 0.31 | 0.52 | 0.74 | 1 |
|---|---|---|---|---|---|---|
| 位移（vmin） | 0, 0 | −3.04, 1.76 | 2.74, −1.76 | −1.76, 0.97 | 0.97, −0.48 | 0, 0 |

### 数字弹一下

停表那一格的数字（`.display`）以自身中心为原点缩放，共 0.38 秒，整段用 `ease-out`、
关键帧之间线性：

| 进度 | 0 | 0.18 | 0.5 | 1 |
|---|---|---|---|---|
| 缩放 | 1 | 1.112 | 0.98 | 1 |

只缩放，读数不变。放大时数字会短暂越过格子边缘（普通模式下数字本来就几乎占满屏幕，
两端会被屏幕边缘裁掉一点），随即落回。

### 冲击环

从停表那一格数字的中心出现，向外扩散，共 0.5 秒，`ease-out`：

| 进度 | 外径 | 线宽 | 不透明度 |
|---|---|---|---|
| 0 | 8.3 vmin | 2.8 vmin | 0.9 |
| 1 | 138 vmin | 0.3 vmin | 0 |

- 颜色取本格颜色的浅色版（与白色约七三混合），压在同色数字上也看得见：

  | 场合 | 数字颜色 | 环的颜色 |
  |---|---|---|
  | 普通模式、PK 红方 | `#ff2d2d` | `#ffc2bd` |
  | PK 蓝方 | `#3d8bff` | `#c4dcff` |
  | 普通模式带 `?green` | 停表这一刻转成 `#2dff6a` | `#c0ffd2` |

- 环盖在数字上面；PK 模式下在 VS 下面。环会超出屏幕，被页面裁掉。

## 4. 不影响计时

- 停表的成绩在拍击那一刻就按事件时间戳算好、写到屏幕上了，动画在那之后才开始。
- 整段动画（最长 0.5 秒）落在停表后 500 ms 的锁定期内，这段时间本来就不接受下一拍。
  PK 模式下红方停表后蓝方最早在 0.5 秒后才能开始，所以两次冲击不会叠在一起。
- 动画只改 `transform`、`opacity` 与冲击环的尺寸，不改排版，色条高度、数字大小不受影响。
- PK 模式下砸入还没播完就停表了（清场后立刻开始、立刻停）：两段抖动都在 `#stage` 上，
  后开始的停表抖动生效；它先播完，砸入剩下的部分接着播。不额外处理。
- 浏览器不支持 Web Animations API（`element.animate`）时静默跳过。

## 5. 实现

### DOM

每格在 SVG 后面加一个冲击环：

```html
<div class="slot" data-side="red" data-slot-state="empty">
  <div class="stripe"></div>
  <svg class="display" ...>...</svg>
  <span class="hit-ring"></span>
</div>
```

普通模式用的就是红方那一格（蓝方那一格隐藏），不用另加。

### CSS

- `:root` 新增三个颜色：`--ink-hit`（`#ffc2bd`）、`--ink-blue-hit`（`#c4dcff`）、
  `--ink-green-hit`（`#c0ffd2`）。
- `.hit-ring`：绝对定位，`transform: translate(-50%, -50%)`，平时尺寸为 0、不透明度为 0，
  与 `.vs-ring` 写法一致。边框颜色默认 `--ink-hit`；蓝方那一格用 `--ink-blue-hit`；
  带 `?green` 时（`:root[data-green-stop]`，只在普通模式出现）用 `--ink-green-hit`。`z-index: 1`。
- `#stage` 加 `position: relative`，作为冲击环的定位容器。
- `.vs-box` 的 `z-index` 由 1 改为 2：两格的数字带 `filter`，各自形成层叠上下文，
  环不提层级就会被下一格的数字盖住；VS 要再高一层，压在环上面。

### 新模块 `hit.js`

```js
export const HIT_MS = 380;
export function stopHit({ digits, ring, stage }) // 播一次停表冲击；不支持 element.animate 时什么都不做
```

- 先把冲击环挪到数字中心：`digits` 与 `stage` 的 `getBoundingClientRect()` 中心相减，
  写到环的 `left`、`top` 上。两个矩形同受整屏抖动的平移，相减后与抖动无关；
  数字的缩放以中心为原点，也不改变中心。
- 三段关键帧写成模块里的常量。

### `app.js`

- 停表分支在 `stopTiming` 写好成绩之后，对停表那一格调用 `stopHit`：
  - `handleSlapSingle` 进入 `LOCKED` 时，冲击第一格
  - `handleSlapPk` 进入 `LOCK_P1`、`LOCK_P2` 时，冲击对应的那一格
- 「减弱动态效果」的判断与砸入共用。

### 离线

`hit.js` 加入 `sw.js` 的 `ASSETS`，`CACHE` 版本号加一。

### 文档

红蓝设计的非目标「停表闪烁或其他任何停表动效」、砸入设计的非目标「开始、停表时的动效」
改为指向本文档。

## 6. 非目标

- 开始计时时的动效
- 停表音效的变化（提示音照旧）
- 力度做成可调，或两种模式用不同力度

## 7. 测试策略

单元测试（`test/hit.test.js`，用记录 `animate` 调用的假元素）：

- 三个元素各收到一段动画，时长与缓动符合第 3 节
- 冲击环的 `left`、`top` 落在数字中心；`#stage` 整体平移时结果不变
- 不支持 `element.animate` 时什么都不做

离线完整性：现有的「页面用到的每个 JS 模块都在缓存清单里」测试覆盖 `hit.js`。

在 headless Chrome 里检查（用 `getAnimations()` 读动画）：

| 场景 | 预期 |
|---|---|
| 普通模式停表 | `#stage`、第一格 `.display` 各有一段 380 ms 的动画，第一格 `.hit-ring` 有一段 500 ms 的 |
| PK 红方、蓝方停表 | 同上，换成停表那一格 |
| 开始、清零（清场）、锁定期内拍 | 不新增停表冲击 |
| 普通模式横竖屏，PK 三种排法（800×360、360×800、1024×768） | 冲击环中心与数字中心重合 |
| 冲击环颜色 | 普通 `#ffc2bd`，`?green` 下 `#c0ffd2`，PK 红方 `#ffc2bd`、蓝方 `#c4dcff` |
| 模拟「减弱动态效果」 | 停表不播 |
| 动画播完之后 | 复跑脊柱设计的外观检查，排版与改动前一致 |
| 停表 | 成绩仍按按键事件的时间戳计算 |

另截取停表后的几帧，确认抖动、数字弹大与冲击环出现；PK 模式下环在 VS 下面、在另一格数字上面。

## 8. 验收标准

1. 普通模式与 PK 模式下停表，整屏抖一下，停表那一格的数字弹大再落回，并从数字中心扩散出本格颜色的浅色环，0.5 秒内结束
2. 开始、清零（清场）、计时中不播
3. 动画播完后，各种屏幕下的外观与位置和现在完全一致
4. 开了「减弱动态效果」时不播
5. `?green` 下冲击环是浅绿色
6. 计时结果的取得方式不变
7. 断网打开照常播放
8. 全部 `node --test` 测试通过
