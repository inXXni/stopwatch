# 拍击提示音设计文档

日期：2026-10-28
基础：`2026-10-27-slap-stopwatch-design.md`（下称「秒表设计」）

## 1. 背景与目标

现在拍一下没有任何声音，拍的人只能盯着屏幕确认这一拍有没有被收到。
加一声提示音：**每拍一下都响一声「滴——」，只有清屏那一拍不响**，普通模式和 PK 模式都一样。

声音参照一段「计时接力」短视频里实体计时器的提示音，用户在演示里对比原声与复刻版后选定。

## 2. 声音

### 参照的原声

从视频音轨里分析出来的（视频里拍按钮的「啪」声已排除）：

| 项 | 实测 |
|---|---|
| 频率 | 2461 Hz，常见压电蜂鸣片的共振频段 |
| 时长 | 约 0.4 秒 |
| 音色 | 接近纯音：二次谐波比基频低 16.5 dB，三次谐波低 27.7 dB；不是方波 |
| 起伏 | 约 40 ms 响起，之后 0.3 秒内渐强 4～5 dB，最后约 30 ms 收掉 |

视频里的计时器只在开始计时时响；本设计改为除清屏外每拍都响（见第 3 节）。

### 复刻参数

用 Web Audio 实时合成，不带音频文件：

- 振荡器频率 2461 Hz，波形用 `PeriodicWave` 叠加三个分量：基频 1、二次谐波 0.15、
  三次谐波 0.041（即 −16.5 dB 与 −27.7 dB）
- 音量包络（`t` 为开始时刻，`G` 为峰值增益）：

| 时刻 | 增益 |
|---|---|
| `t` | 0 |
| `t + 0.040 s` | `0.6 × G` |
| `t + 0.340 s` | `G` |
| `t + 0.375 s` | `G` |
| `t + 0.400 s` | 0 |

- `G` 初值 0.5。演示里用的是 0.25，手机外放比电脑小，比赛现场又吵，所以先加大一倍，
  真机上听过再定。`PeriodicWave` 默认把波形归一化到峰值 1，所以波形峰值就是 `G`，
  `G` 不超过 1 就不会削波。

## 3. 什么时候响

**除清屏那一拍外，每一拍都响，同一个声音。** 「一拍」与秒表现有的输入规则一致：

| 输入 | 响不响 |
|---|---|
| 第一根落下的手指（`pointerdown`） | 响 |
| 同时落下的其余手指（已被忽略） | 不响 |
| 键盘 Enter（`keydown`，非自动重复） | 响 |
| 按住 Enter 产生的自动重复 | 不响 |

开始、停表都响，停表后 500 ms 锁定期内被吞掉的那一拍也响。响声表示「设备收到了这一拍」，
这一拍做了什么仍以屏幕为准。

**清屏那一拍不响**（2026-10-28 上线后的调整）：普通模式成绩出来后拍一下清零、
PK 模式两人都停后拍一下清场，这一拍不响。响不响按拍击之前的状态判断，
由 `timer-core.js` 的纯函数 `slapBeeps(state)` 决定：拍击前是 `STOPPED`（普通模式）
或 `RESULT`（PK 模式）就不响，其余都响。

### 连续快拍

提示音长 0.4 秒，拍得快时前一声还没响完。新的一拍到来时，前一声在 5 ms 内淡出并停止，
新的一声从头开始，像实体蜂鸣器一样一拍一声，不会叠成更响的一团。

## 4. 不影响计时

- 时间戳仍取自事件本身的 `event.timeStamp`（秒表设计第 5 节）。先处理拍击、记下时间，
  再发声。
- 发声只是把振荡器交给浏览器的音频线程，立即返回，不等待声音播完。
- 浏览器不支持 Web Audio、音频初始化失败等情况一律静默忽略，不能抛错影响计时。

## 5. 实现

### 新模块 `beep.js`

```js
export function createBeeper() // 返回 { beep() }
export function beepEnvelope(t, gain) // 返回包络的时间点列表 [[时刻, 增益], …]，纯函数
```

- 第一次 `beep()` 时才创建 `AudioContext`：浏览器只允许在用户操作中启动音频，
  第一拍本身就是一次用户操作，所以从第一拍起就能响
- 每次 `beep()` 前若 `AudioContext` 不是 `running`（例如切到别的应用再回来被系统挂起），
  先 `resume()`
- `PeriodicWave` 只建一次，之后复用
- 包络按 `beepEnvelope` 返回的时间点逐个写入增益参数；它是纯函数，可用 `node --test` 覆盖

### `app.js`

在 `onPointerDown`（确认是第一根手指之后）与 Enter 的 `keydown` 处理里，
`handleSlap(e.timeStamp)` 之后调用 `beeper.beep()`。

### 离线

`beep.js` 加入 `sw.js` 的 `ASSETS`，`CACHE` 版本号加一。声音本身是合成的，
不需要缓存任何音频文件。

## 6. 已知限制

- **声音略晚于拍击**：安卓手机外放本身有几十毫秒延迟，蓝牙音箱或耳机可能到一两百毫秒。
  只影响听感，不影响成绩。
- **第一声可能稍晚**：第一拍时音频引擎才启动，第一声可能比之后的晚一点。
- **iPhone 的静音键会把它静音**：网页音频受静音键控制。
- **音量跟随手机的媒体音量**：不想要声音就把媒体音量调到 0。

## 7. 非目标

- 声音开关、音量设置、用地址参数关掉声音
- 开始与停表用不同的声音
- 倒计时提示音、震动

## 8. 测试策略

纯逻辑部分用 `node --test` 覆盖：

- `beepEnvelope`：从 0 开始、在 0.4 秒回到 0；峰值等于 `G`；时间点递增
- 离线完整性：`app.js` 直接或间接导入的每个模块都在 `sw.js` 的 `ASSETS` 里
  （漏掉 `beep.js` 的话，离线时页面加载不了这个模块）

在 headless Chrome 里拦截振荡器的 `start`，统计每一拍发出几声：

- 普通模式与 PK 模式各走一轮，每一拍各响一声，包括锁定期内被吞掉的那一拍；清屏那一拍不响
- 同时落下第二根手指：不多响
- Enter 自动重复：不响
- 两拍间隔 0.1 秒：第一声在第二拍时被停掉

手机真机上外放听：音量是否够、声音是否和演示里一样、拍击到出声的延迟是否能接受。

需要同步修改的旧文档：秒表设计第 7 节「交互细节」加一条，说明每拍都响提示音，详见本文档。

## 9. 验收标准

1. 普通模式与 PK 模式下，每拍一下（屏幕或 Enter）都响一声「滴——」，包括锁定期内的拍；
   清屏（清零、清场）那一拍不响
2. 同时落下的多根手指、按住 Enter 的自动重复不额外响
3. 连续快拍时一拍一声，不叠在一起
4. 声音与演示里的「视频同款」一致，手机外放在比赛现场听得清
5. 加了提示音后，计时结果的取得方式不变（仍取事件时间戳）
6. 断网后打开，提示音照常
7. 全部 `node --test` 测试通过
