# 手拍秒表（Slap Stopwatch）设计文档

日期：2026-10-27

## 1. 背景与目标

魔方速拧比赛现场使用的大字秒表。选手拍一下屏幕开始计时，完成后再拍一下停止，
全场通过屏幕上的大号数字读取成绩，成绩由人工记录。

核心目标：**在手机或平板上打开就能当一块可靠的大秒表用，不依赖网络。**

## 2. 非目标（明确不做）

以下功能经确认不在范围内，不要实现：

- 成绩列表、历史记录、ao5/平均值统计、个人最好成绩
- 魔方打乱公式生成
- 赛前 15 秒观察倒计时
- +2 / DNF 罚时标记
- 选手名单、轮次管理、排名
- 多设备状态同步、投屏
- 任何后端服务、账号体系、数据上报

## 3. 形态与部署

纯静态 PWA，三个文件，无依赖、无构建步骤：

```
timer/
├── index.html      # 结构与样式
├── timer-core.js   # 纯逻辑：时间格式化、状态机、幽灵层文本（可单独测试）
├── app.js          # DOM 绑定、渲染循环、Wake Lock
├── manifest*.json  # PWA 清单，按参数组合各一份，由 tools/make-manifests.mjs 生成
├── sw.js           # Service Worker，缓存上述文件以支持离线
└── fonts/          # DSEG7 七段字体与其 SIL OFL 许可证
```

纯逻辑之所以单独成文件，是为了不依赖 DOM、能用 `node --test` 直接测试。

部署方式为把目录发布到任意静态托管（GitHub Pages / Cloudflare Pages / Artifact 链接均可）。
用户在手机浏览器打开后，需要**安装**成桌面应用（Android Chrome：菜单 →「添加到主屏幕」→「安装」；
iOS Safari：分享 →「添加到主屏幕」），再从桌面图标启动才是全屏。在浏览器标签页里打开，
或选「创建快捷方式」，都只是普通标签页，地址栏和工具栏会一直显示。

### 安装与参数

普通模式的两种参数组合与 PK 模式各有一份独立的 manifest，各自写明 `start_url`：

| 文件 | 启动页 | 图标名 |
|---|---|---|
| `manifest.json` | `./` | 秒表 |
| `manifest-green.json` | `./?green` | 秒表 绿 |
| `manifest-pk.json` | `./?pk` | PK 秒表 |

PK 模式忽略 `?green`（红蓝是阵营色，停表变绿会把阵营抹掉），`?pk&green` 用的也是
`manifest-pk.json`。

`index.html` 不写死 manifest 链接，由头部的一段内联脚本按地址参数插入对应文件的链接，
并同步 iOS 的 `apple-mobile-web-app-title`。三份文件由 `npm run manifests` 生成，不手改。

为什么这样做：

- 安装后的图标总是打开 manifest 里的 `start_url`。只有一份 manifest 时，
  从 `?pk` 页面装出来的图标打开的是普通模式，参数会丢；`id` 默认取 `start_url`，
  几种组合还会被当成同一个应用，只能装一个。
- 不能靠省略 `start_url` 让它跟随安装时的地址：Chrome 要求显式写出 `start_url`
  才允许安装，省略会报 `start-url-not-valid`，「安装」选项直接消失。
- 不能先写死一份默认的链接再用脚本改 `href`：Safari（WebKit）一看到第一个 manifest
  链接就立刻加载并记住它，之后改 `href` 不会重新加载，「添加到主屏幕」用的仍是默认那份。
  2026-10-28 发现 iPad 上从 `?pk` 添加，存下的地址不带参数，就是这个原因；
  安卓 Chrome 在安装时才读当前的链接，不受影响。

Service Worker 查缓存时用 `ignoreSearch: true`：几种参数打开的都是同一个 `index.html`，
缓存里存的是不带参数的地址，不忽略参数的话带参数的地址断网时打不开。

Service Worker 安装时用 `cache: 'reload'` 取文件，绕过浏览器的 HTTP 缓存。
本地服务不写缓存头，浏览器按修改时间估算新鲜期；GitHub Pages 让浏览器缓存 10 分钟。
不绕过的话，新版安装时可能拿到浏览器缓存里的旧 `index.html`、`app.js`，
新缓存里混进旧文件，刷新多少次都还是旧版。2026-10-29 加 VS 砸入时在本地浏览器上遇到过：
新缓存里只有 `slam.js` 是新的。

选择 PWA 而非普通网页的理由：需要桌面图标、全屏无浏览器 UI、以及离线可用——
比赛现场网络不可靠，离线能力是硬需求。

## 4. 状态机

四个状态，由单一的 `state` 变量驱动：

| 状态 | 显示内容 | 可接受的输入 | 转移 |
|---|---|---|---|
| `IDLE` | `0.00` | 拍击 | → `RUNNING`，记录起始时间戳（取自事件） |
| `RUNNING` | 实时走动的时间 | 拍击 | → `LOCKED`，记录结束时间戳（取自事件） |
| `LOCKED` | 最终成绩（静止） | 忽略全部输入 | 500ms 后自动 → `STOPPED` |
| `STOPPED` | 最终成绩（静止） | 拍击 | → `IDLE`，清零但不开始计时 |

`LOCKED` 是 A 方案成立的关键：手掌拍下时会发生反弹，且多根手指会在数十毫秒内
产生多个独立的触摸点，若不锁定，停止的那一拍会立刻把下一轮也启动。

三拍一轮：拍一下开始、拍一下停表、拍一下清零，再拍才开始新一轮。
停表后那一拍只清零不开跑，成绩出来后手快多拍一下不会直接把成绩抹掉。

误触发的恢复路径：拍一下停止、再拍一下清零，即可重新开始，无需额外的重置操作。

## 5. 计时精度

- 时间源使用 `performance.now()`，不使用 `Date.now()`。后者受系统对时影响，
  可能在计时过程中发生跳变，导致成绩错误。
- 经过时间一律由「结束时间戳 − 起始时间戳」计算得出，不做逐帧累加。
  累加会随掉帧累积误差。
- 画面更新由 `requestAnimationFrame` 驱动。掉帧只影响显示平滑度，不影响计时准确性。
- 起始与结束时间戳均取自 `pointerdown` 事件的 `event.timeStamp`，而非回调执行时刻
  调用 `performance.now()` 的返回值，以排除事件派发与 JS 执行的延迟。
  `event.timeStamp` 与 `performance.now()` 同为相对 `performance.timeOrigin` 的
  高精度时间戳，可直接相减。

## 6. 显示

外观为七段数码管（LED 显示屏）风格。

- 格式固定为 `SS.ss`，例如 `12.34`。常规成绩不会超过 60 秒，因此不显示分钟。
- 秒数始终补足两位，四位数字全程点亮：`0` 显示为 `00.00`，`9.87` 显示为 `09.87`。
  不补零的话，待机的 `00.00` 一开始计时就变成 `0.01`，最左那位会突然熄灭。
- 超过 60 秒时秒数继续累加（`75.21`），不切换为分钟格式。这是兜底行为，
  保证极端情况下不出错，而非常规路径。
- 字形使用 DSEG7 Classic 七段数码管字体（SIL OFL 1.1），随项目分发，不走 CDN。
  该字体天然等宽，因此不需要 `tabular-nums`——比例字形下 `1` 比 `8` 窄，
  计时过程中数字会持续左右抖动。
- 读数下面垫一层固定为全 `8` 的幽灵层，以低透明度显示，模拟 LED 显示屏上
  没通电的段——幽灵层露出的正是每一位里没点亮的那几根段。
  两层右对齐叠放；秒数补足两位后两层等长，超过 99 秒时幽灵层跟着加宽，
  布局始终由幽灵层决定，数字不会随位数变化而整体缩放。
- 配色为纯黑背景 + 高亮度发光数字，保证现场远距离可读。
- 待机、计时、停表三种状态同为亮红，与实物 LED 牌一致——待机时的 `00.00`
  同样是点亮的，不做暗显。三者靠数字是否跳动、以及读数本身来区分。
  带 `?green` 查询参数访问时，停表后转为绿色，便于一眼确认表已停止。
  参数写在 URL 里而非做成界面开关，是为了「添加到主屏幕」时能把选择固化进图标。
- 文字放在 SVG 内，viewBox 按幽灵层的实际墨水范围测量后设置，
  再由 `preserveAspectRatio` 等比缩放填满容器。字号因此不需要手算 vw/vh，
  各种屏幕比例都能占满。字体是异步加载的，加载完成后必须重新测量一次。
- 容器内边距取固定边距与 `env(safe-area-inset-*)` 的较大者，
  否则横屏时数字会被 iPhone 刘海挡住。
- 计时期间申请 Wake Lock 保持屏幕常亮；不支持该 API 的浏览器静默降级。

## 7. 交互细节

- 监听 `pointerdown` 而非 `click`。`click` 需要等待 `pointerup` 且在移动端存在延迟。
- 整个视口为触发区域，不设独立按钮，避免选手需要瞄准。
- 仅响应第一个触摸点，忽略同时落下的其余手指。
- 必须禁用以下默认行为，否则拍击会触发非预期的浏览器响应：
  - `touch-action: none` —— 禁止滚动与手势
  - `user-select: none` —— 禁止文字选中
  - `overscroll-behavior: none` —— 禁止下拉刷新与橡皮筋效果
  - 禁用双击缩放与长按上下文菜单
- 每拍一下（屏幕或 Enter）都响一声「滴——」，开始、停表与锁定期内被忽略的拍都响；
  清屏（清零、PK 清场）那一拍、同时落下的其余手指、按住 Enter 的自动重复不响。
  详见 `2026-10-28-slap-beep-design.md`。

## 8. 兼容性

目标浏览器为 iOS Safari、Android Chrome，以及桌面浏览器。

- Wake Lock API：iOS 16.4+ 与 Chrome 支持，不支持时降级为不保持常亮，不报错。
- Service Worker：不支持时降级为普通网页，功能不受影响，仅失去离线能力。
- PWA 全屏：需同时提供 `manifest.json` 与 iOS 专用的 `apple-mobile-web-app-*` meta 标签。

## 9. 测试策略

计时与状态逻辑抽取为不依赖 DOM 的纯函数，便于独立测试：

- `formatTime(ms)` —— 毫秒转显示字符串，覆盖零值、进位、超过 60 秒、超长值等边界
- `nextState(state, event)` —— 状态转移，覆盖全部状态与输入的组合，
  特别是 `LOCKED` 状态下输入被忽略

交互与视觉部分（触摸响应、字号自适应、Wake Lock）通过真机手动验证。

## 10. 验收标准

1. 在手机浏览器打开，拍一下开始走表，再拍一下停止并显示成绩
2. 停止那一拍不会意外启动下一轮计时
3. 计时过程中数字不发生左右抖动
4. 计时过程中屏幕不自动熄灭
5. 添加到主屏幕后点开为全屏，无浏览器地址栏
6. 开启飞行模式后仍可正常打开并使用
7. 连续计时 60 秒，与外部秒表对照误差在 ±50ms 以内
