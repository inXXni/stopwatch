# 点 VS 清零设计文档

日期：2026-10-29
基础：`2026-10-29-vs-slam-design.md`（下称「砸入设计」）

> 2026-10-29 起 VS 改为水墨毛笔，下文的「砸一次」「不砸」都改为「写一次」「不写」；第 2 节按位置判断的理由现在是墨点与光晕画到框外，见 `2026-10-29-vs-ink-design.md` 第 5 节。

## 1. 背景与目标

用户要求 **PK 模式下点 VS 清零**：不管这一轮进行到哪一步，点一下 VS，两格计时全部归零，
重新等红方拍。例如有人抢拍、误拍时，不用再把剩下的几拍走完才能重来。

用户起初还想让新一轮 VS 砸下来时响一声低音「咚」，看过演示后决定不要，VS 砸入保持无声。

PK 设计（`2026-10-27-pk-mode-design.md`）当初不在界面上放任何按钮，理由是「整块屏幕都是拍击区，
任何按钮都可能被误拍」。点 VS 清零打破了这一点：拍表时手掌落在 VS 上，就会把这一轮清掉，
包括正在计时的成绩。用户看过三种做法（点一下就清零、按住才清零、只在不计时时清零）后，
明确选了「点一下就清零」，接受这个风险。

## 2. 什么算点到 VS

只在 PK 模式下（普通模式没有 VS）。按下的位置落在 VS 的黑底框（`.vs-box`）里就算，
与 VS 当前的排法无关：

| 排法 | 能点到的范围 |
|---|---|
| 宽屏横屏（色条脊柱） | 左侧 26 vmin 宽的黑底框，截断两根色条的那一块 |
| 竖屏 | 中间的「VS」字样 |
| 其余横屏 | 中间的「VS」字样 |

两侧的细线、两行之间的空白不算。点到范围之外的地方照常是拍击。

按落点的位置判断，不看手指落在哪个元素上。VS 砸入的开头，文字放大到 3.4 倍、完全透明，
按元素判断的话，清场后紧跟着的那一拍若落在 VS 附近，会碰到这块看不见的放大文字，被当成点 VS。

和拍击一样在**按下**的那一刻生效，也一样只认第一根落下的手指：
先落下的手指在别处，后落在 VS 上的手指不算；先落在 VS 上，同时落下的其余手指也不算拍击。

Enter 键没有对应的清零，行为不变。

## 3. 点了之后

| 当时的状态 | 结果 |
|---|---|
| 等红方拍、红方计时中、等蓝方拍、蓝方计时中、两人都已停 | 清零：两格显示 `00.00`，回到等红方拍，VS 砸下来 |
| 红方或蓝方刚停表的 500 ms 锁定期 | 不理会，与锁定期内的拍击一样 |

- 锁定期照样挡住：停表那一拍的手掌弹起再落下，正好落到 VS 上，会把刚停下的成绩清掉，
  锁定期就是为了挡这种二次触发。
- 已经在等红方拍、两格都是 `00.00` 时点 VS，状态不变，但照样砸一次，让人知道点到了。
- 清零不出声：不响「滴」，也不响「咚」，与清屏那一拍一样。
- 计时中被清零时，那一格的读数直接归零，不先停表、也不播停表爆裂。
- 开了「减弱动态效果」时照样清零，只是 VS 不砸（砸入设计）。

## 4. 实现

### `timer-core.js`

`Event` 加 `RESET`。`nextPkState(state, Event.RESET)`：两个锁定状态原样返回，其余都返回 `WAIT_P1`。
普通模式的 `nextState` 不认 `RESET`，原样返回。

### `app.js`

- `resetPk()`：按 `Event.RESET` 推进状态，被锁定期挡住就返回；否则停掉计时、两格归零、
  刷新色条、调用 `slam()`。
- `onPointerDown`：认定第一根手指之后，PK 模式下落点在 `.vs-box` 的外框
  （`getBoundingClientRect()`）里就调用 `resetPk()`，否则照常拍击。

### 离线

不新增文件，`sw.js` 的 `CACHE` 版本号加一。

### 文档

- PK 设计里「不在界面上做开关」那一句加注：VS 例外，见本文档。
- 主设计的交互一节加一条点 VS 清零。

## 5. 非目标

- 按住才清零、清零前确认
- 新一轮 VS 砸下来时的声音
- 普通模式的清零按钮
- 键盘清零
- 给 VS 加按下态、提示文字等新的外观
- 清零后自动开始计时

## 6. 测试策略

单元测试：`nextPkState` 除两个锁定状态外，各状态收到 `RESET` 都回到 `WAIT_P1`；锁定状态不变。
普通模式 `nextState` 收到 `RESET` 不变。

在 headless Chrome 里检查（触摸用 CDP 的 `Input.dispatchTouchEvent`）：

| 场景 | 预期 |
|---|---|
| 三种排法下，红方计时中点 VS | 两格 `00.00`，回到等红方拍；VS 砸一次；不出声 |
| 等蓝方拍、蓝方计时中、两人都已停时点 VS | 同上 |
| 锁定期内点 VS | 什么都不变 |
| 等红方拍时点 VS | 状态不变，砸一次 |
| 点 VS 两侧的细线、两行之间的空白 | 照常是拍击 |
| 先有一根手指在别处，再点 VS | 不清零 |
| 模拟「减弱动态效果」后点 VS | 清零，不砸 |
| 普通模式 | 拍击行为不变 |
| 清零之后再开始一轮 | 计时、停表爆裂、成绩都正常 |

复跑停表爆裂与脊柱外观的检查，确认没有受影响。

## 7. 验收标准

1. PK 模式下点 VS，除锁定期外，不管在哪一步都清零回到等红方拍，VS 砸下来，不出声
2. 点 VS 以外的地方、Enter 键，行为与现在完全一致
3. 开了「减弱动态效果」时，点 VS 照样清零
4. 普通模式不受影响
5. 计时结果的取得方式不变
6. 全部 `node --test` 测试通过
