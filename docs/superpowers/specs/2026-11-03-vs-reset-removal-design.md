# 撤掉「点 VS 清零」设计文档

日期：2026-11-03
基础：`2026-10-29-vs-reset-design.md`（下称「清零设计」）

## 1. 背景与目标

清零设计让 PK 模式下点一下 VS，除停表后的锁定期外，两格立刻归零、回到等红方拍，不出声。

用户在 iPad 上遇到：开始计时后再拍一下，成绩没出来，两格直接归零。原因是：

- iPad 屏幕接近方形，VS 排在上下两格中间，正好压在屏幕正中。
  判定框在 1180×820 横屏约 84×58 px，在 820×1180 竖屏约 170×114 px
- 拍屏幕中间就落在 VS 上，触发静默清零：不停表、不响，这一轮成绩直接没了
- 手机横屏用的是色条脊柱排法，VS 在左边，拍中间碰不到，所以手机上没遇到

无头 Chrome 按 iPad 尺寸复现过：第一拍在红格开始，第二拍在屏幕正中，两格归零；
两拍都在数字上，或用蓝牙 Enter，都正常停表。

用户决定撤掉这个功能。

## 2. 撤掉之后

- 整块屏幕重新都是拍击区，点 VS 和点别处一样：开始、停表、换人、清场照常，照常响「滴」
- 锁定期、只认第一根手指的规则不变
- 要清零，用原来的路子：两人都停表后再拍一下清场（PK 设计第 6 节）
- VS 的外观不变，仍在打开页面、清场时一笔笔写出来；只是少了「点 VS 清零」这个时机

## 3. 实现

整段删掉，不留关掉的开关或用不到的代码：

| 文件 | 改动 |
|---|---|
| `timer-core.js` | `Event` 去掉 `RESET`；`nextPkState` 去掉处理它的分支与注释里的那一段 |
| `app.js` | 删掉 `resetPk()`、`vsBox`、`onVs()`；`onPointerDown` 认定第一根手指后一律 `slap()`；写 VS 时机的注释去掉「点 VS 清零一次」 |
| `index.html` | `.vs-box` 注释去掉「也是点 VS 清零的判定范围」；`.vs-box` 的样式不变，它仍是黑底，`z-index: 2` 仍要压住停表冲击环 |
| `test/timer-core.test.js` | 删掉三个 RESET 测试，换成一个：`Event` 只有 `SLAP` 与 `UNLOCK` |
| `sw.js` | 缓存版本 v24 |

### 为什么不只关掉判定

只删 `app.js` 里的判定、留着状态机的 `RESET`，以后想恢复会快一点，
但留下一个没人发、却有测试守着的事件，读代码的人会以为还有地方在用。

## 5. 测试

`node --test`：`Event` 只有 `SLAP` 与 `UNLOCK`；其余测试不变、全部通过。

无头 Chrome（触摸事件，不经 Service Worker），iPad 横屏 1180×820、iPad 竖屏 820×1180、
手机横屏 800×360、手机竖屏 360×708 各跑一遍：

- 第一拍在红格开始，第二拍落在屏幕正中（VS 上）：红格停表、出成绩，不清零
- 等红方拍时点 VS：红格开始计时
- 两人都停后点 VS：清场，VS 写一次
- 控制台没有错误

## 6. 验收标准

1. PK 模式下点 VS 与点屏幕别处完全一样
2. iPad 上计时中拍屏幕中间，正常停表出成绩
3. 其余拍击、锁定期、提示音、VS 写出来的行为不变
