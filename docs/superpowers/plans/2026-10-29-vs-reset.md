# 点 VS 清零 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PK 模式下点一下 VS，除停表后的 500 ms 锁定期外，两格都归零、回到等红方拍，VS 砸下来，不出声。

**Architecture:** `timer-core.js` 的 `Event` 加 `RESET`，`nextPkState` 收到它时锁定状态原样返回、其余回到 `WAIT_P1`；普通模式的 `nextState` 不认它。`app.js` 加 `resetPk()`，在 `onPointerDown` 认定第一根手指后，按落点是否在 `.vs-box` 的外框里分流到清零或拍击。按位置判断，不看事件落在哪个元素上：砸入开头 VS 文字放大到 3.4 倍（透明），按元素判断的话，清场后紧跟的那一拍会落在放大的文字上被当成点 VS。

**Tech Stack:** 原生 HTML/CSS/JavaScript（ES module）、Node 内置 `node:test`；集成检查用 headless Chrome + CDP（`Input.dispatchTouchEvent`）。

**Spec:** `docs/superpowers/specs/2026-10-29-vs-reset-design.md`

- [ ] **Step 2: 加 `resetPk`**

紧接在 `handleSlapPk` 函数之后加：

```js
// 点 VS 清零：不出声，计时中的那一格不停表、不播爆裂，直接归零。
// 已经在等红方拍时状态不变，照样砸一次，让人知道点到了
function resetPk() {
  const next = nextPkState(pkState, Event.RESET);
  if (next !== PkState.WAIT_P1) return; // 锁定期内被挡住
  pkState = next;
  stopTicking();
  displays.forEach((d) => d.render(formatTime(0)));
  paintSlots(pkSlotStates(pkState));
  slam();
}
```

- [ ] **Step 3: `onPointerDown` 分流**

把

```js
function onPointerDown(e) {
  // 只认第一根落下的手指，同时落下的其余手指一律忽略
  if (activePointerId !== null) return;
  activePointerId = e.pointerId;
  e.preventDefault();
  slap(e.timeStamp);
}
```

改为

```js
// 按落点位置判断，不看事件落在哪个元素上：砸入开头 VS 文字放大到 3.4 倍（透明），
// 按元素判断的话，清场后紧跟的那一拍落在 VS 附近，会被当成点 VS
const vsBox = stage.querySelector('.vs-box');
function onVs(e) {
  const r = vsBox.getBoundingClientRect();
  return e.clientX >= r.left && e.clientX < r.right && e.clientY >= r.top && e.clientY < r.bottom;
}

function onPointerDown(e) {
  // 只认第一根落下的手指，同时落下的其余手指一律忽略
  if (activePointerId !== null) return;
  activePointerId = e.pointerId;
  e.preventDefault();
  if (isPk && onVs(e)) resetPk();
  else slap(e.timeStamp);
}
```

### Task 5: headless Chrome 集成检查

**Files:**
- Create: `<scratchpad>/vs-reset-check.mjs`（不进仓库）

前提：8080 本地服务在跑新代码；headless Chrome 开着 9222 调试端口。

- [ ] **Step 1: 写检查脚本**

脚本做的事：

- 在页面脚本之前注入监视：
  - 拦截 `Element.prototype.animate`，记下每段动画的目标与时长。砸入是 `vs-text`，停表爆裂是 7 段。
  - 拦截 `AudioContext.prototype.createOscillator`，记下振荡器个数，用来判断出没出声。
  - 用捕获阶段的 `pointerdown` 记下每次按下的 `timeStamp`。
- 触摸用 `Emulation.setTouchEmulationEnabled` 加上 `Input.dispatchTouchEvent`：先 `touchStart`，再 `touchEnd`。
- 读取状态：
  - 两格各自的 `data-slot-state`
  - 两格 `.display` 的 `data-value`
  - `vs-text` 动画的次数
  - 振荡器个数
  - 脚本错误
- 三种排法：
  - 宽屏横屏 800×360（色条脊柱）
  - 竖屏 360×708
  - 其余横屏 640×480
- 点 VS 取 `.vs-box` 外框的中心。
- 拍击取红格数字的中心。

逐条核对设计第 6 节的场景：

| 场景 | 操作 | 预期 |
|---|---|---|
| 三种排法下红方计时中点 VS | 拍一下，等 300 ms，点 VS | 两格 `00.00`，`[next, empty]`；砸入 +1；振荡器不增加 |
| 等蓝方拍时点 VS | 拍、拍，等 600 ms，点 VS | 同上 |
| 蓝方计时中点 VS | 拍、拍，等 600 ms，拍，点 VS | 同上 |
| 两人都已停时点 VS | 拍、拍，等 600 ms，拍、拍，等 600 ms，点 VS | 同上 |
| 锁定期内点 VS | 拍、拍，立刻点 VS | 红格保留成绩，`[done, empty]`；砸入不增加 |
| 等红方拍时点 VS | 刚打开页面，等砸入播完，点 VS | 状态不变，砸入 +1 |
| 点 VS 两侧 | 竖屏点 `.vs` 行内、黑底框左边 20 px；脊柱排法点 `.vs` 行内、黑底框右边 20 px | 当成拍击：红格开始计时，振荡器 +1 |
| 砸入开头紧跟一拍 | 两人都停后拍一下清场，立刻在黑底框外 10 px、仍在 3.4 倍文字范围里的位置拍 | 当成拍击，红格开始计时 |
| 先有手指在别处再点 VS | 一根手指按在红格不松，第二根落在 VS，再一起抬起 | 第一根开始计时，第二根不清零 |
| 减弱动态效果 | 带 `prefers-reduced-motion: reduce` 打开；拍一下，点 VS | 两格 `00.00`，砸入不增加 |
| 普通模式 | 打开 `/`，点屏幕中心（VS 原本所在的位置） | 照常开始计时 |
| 清零之后再开始一轮 | 点 VS 清零后：拍，等 400 ms，拍 | 红格成绩等于两次按下时间戳之差（`formatTime`）；停表爆裂 7 段；`[done, empty]` |
